# Automatic Updates

KiteShell uses GitHub Releases as the distribution source without embedding a GitHub token in the application.

## Release assets

Every update release contains:

- `KiteShell-<version>.dmg`
- `KiteShell-update.json`
- source archive generated by GitHub

The update manifest contains the version, build, DMG name, minimum macOS version, SHA-256, and an Ed25519 signature.

## Trust flow

1. Query `releases/latest` over HTTPS.
2. Download the release manifest.
3. Verify its Ed25519 signature with the public key embedded in KiteShell.
4. Locate the DMG named by the signed manifest.
5. Download to a temporary file without buffering the entire image in memory.
6. Calculate SHA-256 in 1 MiB chunks and compare it with the signed value.
7. Mount the DMG read-only and locate `KiteShell.app`.
8. Copy the bundled updater helper outside the running app.
9. Quit KiteShell, move the old app to a temporary backup, install the new app, and run strict code-signature verification.
10. Restore the backup if installation fails; otherwise reopen KiteShell and remove temporary files.

Automatic checks are throttled to once every 24 hours. Manual checks are always available.

## Signing key

The private Ed25519 update key is release infrastructure and must never be committed, attached to a Release, printed in CI logs, or copied into the application. Only the public key is embedded in `Info.plist`.
